# 0.2.3开发候选迁移差距与验收分母

盘点时点：2026-10-09。0.2.3为开发候选，发行包运行验收尚未完成；0.2.2及更早候选的通过数不继承到本候选。本文件把上游固定基线、原功能清单、当前实现说明和可核验结果分开记录。它不把历史候选的通过数移交给当前发行包，也不据此声称已经达到95%源功能覆盖。

## 可审计分母

`parity-checklist.md` 的“原功能”主表按一个用户任务一行，共35行；其中“上游捐赠入口”标为不适用，因为Windows产品不复用原作者品牌、收款码或账户。因此当前源功能覆盖分母为34项。每项等权，只有该行所有明确用户行为均有当前候选的验收证据才计为完成；按这一口径至少需完成33/34项，才达到95%门槛。行数可逐行复核；它不是按钮数或代码类数。

等权口径下达到95%至少要完成33/34项；未完整通过的复合行按未完成处理，不按子按钮或测试次数拆分加分。现有证据尚不能逐行证明33项完整完成，因此不报告一个猜测的完成百分比。0.2.2的 `ui-full-surfaces-net10-v5` 全量桌面流程43/43通过，独立浮层专项19/19通过且人工查看截图完整；0.2.3候选当前浮层v6为19/19。新版时间线标签有15项离屏像素验收，PNG已保存，但没有新版实机主窗口截图。仍有硬件、真实DogSC工程与长时同步缺口。计为完成前，必须满足该行描述的用户行为及验收条件，并有对应候选的记录；合成媒体只能证明合成链路，不能代替物理设备或真实DogSC工程。

分母来源：[`parity-checklist.md`](parity-checklist.md) 主表；上游提交固定为 `e207d11b111c5e58152238fb64115b2009850547`，本机 `upstream/dogsc` 的 `HEAD` 与其相同。原功能依据为 [`upstream/dogsc/README.md`](../upstream/dogsc/README.md)、`Sources/RecorderCore` 项目/场景/时间线实现、`Sources/DogSCApp` 页面实现及 README 引用的四张截图 `docs/images/{editor,recorder,motion,export}.png`。

## 不能按“缺实现”处理的项目

摄像头、麦克风、多显示器、不同DPI和其它GPU/编码器组合有代码路径或合成测试，但缺少相应设备证据；它们应标为待设备验证。自动更新服务、公开反馈后台、DogSC格式写回则是当前明确未实现。上游捐赠/赞赏入口被有意移除，是授权与品牌处理，不计为迁移失败。特定跨进程窗口探针曾观察到黑帧（见P0条目）；同进程自有窗口链路已取得非黑帧证据，但同条件矩阵尚未完成，当前根因未定。

0.2.2便携包内容检查和源码归档验证只属于该版本，不代表包运行、安装或卸载验收，也不继承到0.2.3候选。0.2.0/0.2.1的播放、录制、安装或卸载报告只属于各自文件与版本，不继承到0.2.2。0.2.3候选的发行包运行验收尚未完成；归档生成状态以对应候选manifest和验证报告为准。功能目标是按34项分母至少有33项完整通过；当前没有逐行证据支持这个门槛，因此不能声称达到95%。视觉要求见 [`visual-quality-contract.md`](visual-quality-contract.md)：Windows可以提供更合适的交互，但整体美感与流畅度须达到DogSC的品质下限，不再要求逐像素相同。真实硬件、真实Mac项目、端到端长时音画和完整包运行仍需分别验收。

## 建议的剩余工作顺序

1. 先用同一受控窗口和静态/动态刺激对照产品raw WGC与SLR首帧、预览及编码输出，复核此前黑帧观测；按同条件可复现结果定位并处理，再检查移动、遮挡、最小化、关闭与跨屏行为。
2. 对当前QPC采集重做完整长测，记录每个刺激的音量会话状态、包SILENT标志、补零与迟到裁切；30秒18/18短测和fixture校正估计不能替代长时同步验收。
3. 对0.2.3候选的同一发行包完成隔离PATH启动、录制暂停、编辑导出、per-user安装/卸载，并审查偏好快照恢复结果；ContentOnly与源码包结果仅证明包内容和源码可构建。
4. 在有物理摄像头/麦克风和多显示器的Windows设备上做录制、错误收尾和跨轨同步；用真实Mac `.dogscproject` 核验导入映射及损失报告。
5. 按视觉品质合同在多DPI环境验收主窗口、检查器、录制条、弹出菜单、下拉框和进度浮层的可读性、键盘焦点、取消返回；不以静态像素差异判失败。
