# Windows 外壳与视觉验收约定

更新：2026-10-09。用户最新指令优先于此前逐像素复刻要求：允许采用更适合 Windows 的交互；DogSC 的视觉品质、整体美感与流畅度作为下限，功能迁移至少 95% 的目标继续有效。风格方向为 Mac 创作工具的克制、清晰与精致，不因采用 Windows 控件而降低品质。

## 设计起点

改造开始时，编辑器已有浅灰工作区、白色内容层和低饱和绿色选择色；主窗口、菜单、下拉列表、录制浮条、备忘录及进度条却来自不同样式路径，主题切换、键盘焦点与弹出层边缘不统一。早期发行包还出现预设名称输入框被压缩、只露出约10px上沿的问题。这些观察是本轮统一外壳与输入布局的起点。

## 采用的机制与本产品改变

- 内容层保持稳定、可读；短暂浮层通过内边距、细边框和柔和阴影表达层级。弹出层与触发控件保持空间关系，不把每一块区域都做成玻璃。
- 所有菜单和下拉项使用同一文字、选择、禁用、悬停与焦点规范，支持方向键、Enter、Esc、屏幕边缘避让和滚动。颜色跟随当前主题。
- 录制、导出等长任务明确显示真实阶段、已用时间和有依据的剩余时间。取消立即响应，完成、取消、失败和重试沿用真实引擎状态。
- 动效用于解释出现、选择和任务状态；可中断，输入无需等待。遵循 Windows 减少动画与高对比度设置。
- 外壳技术以当前稳定的 Windows API 和可重复实验决定。WinUI 3、Windows App SDK 与当前 WPF 的互操作须验证预览、焦点、多窗口、部署和资源占用，不能以框架名称代替验收。

## 状态与返回路径

浮层按 Esc 或点击外部返回触发控件；嵌套菜单保留键盘方向导航。模态输入保留完整输入区域、默认确认与取消；关闭后恢复所有者交互。导出开始时锁定会影响任务的参数，取消后等待引擎清理再允许重试；错误可读且不会被成功样式覆盖。

## 验证办法

同一合成工程、相同窗口尺寸逐项检查浅色/深色、弹出/选中/禁用、长文本、空数据、进度/取消/失败/完成。至少覆盖 100%、150%、200% 的布局与缩放，记录实际机器可覆盖范围。用实际键鼠、UI Automation、截图和真实导出分别验证；截图不证明性能，编译不证明审美通过。新版应与上游参考及当前版本同时比较，记录有意保留的 Windows 差异。

## 当前实现与证据

0.2.4延续统一菜单、下拉、提示、进度和辅助窗口主题；短暂窗口使用非分层WPF外壳、WindowChrome及DWM圆角。设置、导出和对话框采用可滚动正文与稳定操作区，预设输入框不再被固定高度压缩。系统减少动画和高对比度资源已有实现；本轮尚未完成高对比系统模式验收。

0.2.4发行包UIA全量43/43、浮层19/19通过；包内导出面板15项、编辑回归53项、录制条虚拟生命周期5项通过，并保存12张窗口状态图。此前时间线离屏像素探针15项通过，对比度5.81–9.03，负向对照能拒绝旧黑字问题。离屏探针不创建窗口、不加载录屏媒体，不能代替实机观察。

0.2.4发行包交互已在本机单显示器150%缩放环境验收通过。100%下旧包的Smoke工作区适配测试20/20通过，但由harness移动测试窗；200%下新开发快照的只读主窗启动定位20/20通过，窗口 `[32,32..3808,2032]` 位于工作区 `[0,0..3840,2064]`。旧0.2.4包负对照未通过，且不含此定位修复；新快照不是0.2.5发行包。完整DPI交互、多显示器和高对比系统模式仍待验。12张窗口状态图由测试报告归档，视觉人工检查不等同于覆盖所有参数和工程素材，也不代表用户已认可最终审美。

## 已核验资料

- [WinUI 3](https://learn.microsoft.com/en-us/windows/apps/winui/)：微软推荐用于新 Windows 桌面应用的原生框架。
- [Windows App SDK](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/)：支持既有 WPF/Win32 应用渐进采用现代能力。
- [WPF .NET 10](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/whats-new/net100)：Fluent 样式、输入、字体及 UIA 性能改进；官方也说明 Fluent 样式仍在完善。
- [Mica](https://learn.microsoft.com/en-us/windows/apps/design/style/mica)：面向长期窗口的基础材质，具有失焦及高对比等回退规则。
