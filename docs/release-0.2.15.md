# 0.2.15 暂停后的播放恢复

暂停时保留视频解码器、GPU渲染器、场景素材和已打开的音频代理。再次播放直接复用；项目内容、源文件或预览尺寸改变时才重建对应播放资源。下一帧提前解码和合成，到播放时刻提交。播放准备期间也可以暂停；快速播放、暂停、再播放按最后一次操作执行。暂停保留当前帧，鼠标悬浮继续保持最后点击的画面。

此前每次播放都会重新探测素材、创建渲染器、启动FFmpeg管线，有声音时还会关闭并重新打开MediaElement。暂停使用同步进程取消，旧播放任务与下一次启动也可能交叠。现在启动和解码离开输入线程，播放任务串行交接，取消播放与销毁项目资源分开。原生解码沿用0.2.14已经验证的libav/PTS路径；不支持的素材继续回退CLI。

## 测量

本机后台真实MainWindow探针，1440×810输出。每组三次暂停恢复，表中为最小至最大；原始记录位于 `artifacts/validation/playback-resume-0.2.15/`。

| 素材及模式 | 输入返回 | 播放准备完成 | 首个前进帧提交 |
|---|---:|---:|---:|
| 合成静音，30帧 | 0.33–0.61 ms | 2.21–2.97 ms | 46.60–47.83 ms |
| 合成音频，30帧 | 0.29–1.20 ms | 2.20–3.57 ms | 46.86–47.00 ms |
| 真实4K60录屏，30帧预览 | 0.40–0.86 ms | 3.04–4.30 ms | 47.11–48.06 ms |
| 同一真实4K60录屏，60帧预览 | 0.38–0.65 ms | 3.23–4.47 ms | 30.67–32.05 ms |

0.2.14同一合成静音素材的恢复准备为166.62–187.88 ms，输入返回7.63–9.30 ms；其快速播放、暂停、再播放用例没有恢复画面。旧探针未单独记录首个前进帧，不据此计算该指标的提升比例。新版准备完成时可能先复用暂停帧，因此将准备时间和真正前进的画面分别列出。

首个前进帧通过MainWindow赋图像并更新播放头后的回调测量，额外保留Dispatcher轮询上界；不是屏幕呈现或端到端输入延迟。30/60帧分别包含约33/17 ms的正常帧间隔。没有显示或激活窗口，没有改变原工程，SHA前后一致。音频路径实际生成代理并打开MediaElement，Volume=0且IsMuted=true，证明管线和时钟可用，未做物理扬声器听感验收。

首次起播仍需初始化：本次合成静音约261 ms、带音频约958 ms、真实4K静音约364 ms。这不属于已经准备好的暂停恢复，长项目首次生成混音代理仍可能耗时。

## 验证

`final-silent`、`final-audio`、`final-real-4k`、`final-real-4k60`均通过：暂停画面稳定、三轮会话复用、换项目重建、快速连点最后请求成功、持续播放超过音频校正间隔、自然结束与从头重播。音频打开次数在三轮恢复中保持1；换项目后变为2。生产清理释放会话并删除自己创建的代理，探针额外删除孤儿文件数为0。

`native-final/result.json`验证重排和变速的sourceTime、重复/正反向帧读取、与参考渲染逐像素一致、一个libav会话和零FFmpeg子进程启动，并确认销毁后素材可独占打开。Core、Render.Probe及Integration通过，包含1080p60同步和跨剪辑音轨范围导出；日志为 `required-tests.log`。时间线悬浮保持15项、真实预览调度13项、尺寸/清晰度12项、离屏主题111项通过。首次新增的播完重启测试误把播放头重新设到尾部前0.25秒而超时；修正测试操作后四组完整播放检查通过，失败日志保留。

两个播放探针已接入 `scripts/test.ps1 -IncludeVisualProbe`；原生播放探针接入 `-IncludeMediaProbe` 和源码ZIP独立构建流程。包内容与独立源码重建状态，以 `artifacts/release/FrameTrail-0.2.15-candidate-manifest.json` 为准。

完整Visual/Release回归通过，日志为 `artifacts/validation/visual-release-mainwindow-lifetime-20261010.log`。新增异步清理暴露了旧离屏探针直接关闭MainWindow时缺少Dispatcher上下文的问题，已统一测试窗口的释放路径；清理错误会让检查失败，不再吞掉或在PASS后崩溃。此处是测试工具修复，未改动正常桌面窗口的退出规则。
